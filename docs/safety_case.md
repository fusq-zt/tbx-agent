# TBX-Agent 工程安全说明

> 本文描述当前源码的工程边界和失败语义。TBX-Agent 是研究原型，不是临床认证、医学审查
> 意见或监管合格证明。软件测试、数据集指标和检索 fixture 都不构成临床验证。

## 1. 系统能做什么

TBX-Agent 把当前胸片、病例状态和经审核的指南片段组织为一条有界工具链。它可以按用户问题：

- 运行三分类筛查并保留 `healthy / sick_non_tb / tb` 的相对分数与 argmax；
- 按需调用 D-FINE 显示候选区域；
- 按需检查图像质量、肺野和确定性空间关系；
- 查询当前病例已有证据和既往检查是否存在；
- 检索经审核的指南片段并返回可追溯 citation；
- 在对话中启动主动筛查问答；
- 对批量筛查结果建立独立的复核任务。

三分类分数不是经过临床校准的患病概率，候选框不是诊断结论，检索命中也不是医学事实验证。
系统不实现个体化处方、可靠的纵向进展判断或临床最终报告。

## 2. 当前 Agent 主链

当前主链采用 ReAct 决策与可选规划，由 LangGraph `StateGraph` 的固定节点与条件边执行：

```text
用户问题
  -> load：读取授权病例、有限对话上下文和预算
  -> decide：结构化语义决策，选择回答、单个工具或可选规划
  -> plan（按需）：整理复合目标、条件和证据依赖
  -> execute_tool：校验枚举、权限、成本、病例前置条件后执行
  -> observe：记录真实 ToolReceipt，必要时重读病例
  -> decide / replan / finalize：由条件边选择继续、修订或终止
  -> 只用已批准事实组成最终回答
```

默认预算为：最多 5 个决策步骤、4 次工具调用、3 次高成本视觉调用和 10 个成本单位。预算可在
部署配置中收紧，但不能超过模型字段定义的硬上限。一次 `decide` 只允许零或一个工具调用。

### 2.1 图状态与工具目录

模型可见工具只有四个：

```text
classify_cxr
localize_cxr
analyze_lung_anatomy
search_tb_knowledge
```

普通问答、问候、能力说明、病例状态、上传时质控和未实现的纵向比较都不是工具。能力说明来自代码
拥有的产品元数据；“汇总当前已完成分析”只从公开病例证据做确定性投影，二者都不调用 LLM 去解释
私有 `case_state`，也不产生工具回执。
`TaskSpec` 仅用于读取旧轨迹的兼容投影，不是主语义路由器，也不授权工具。

可演化图状态只保留脱敏 Plan、简短 Observation、预算、当前动作、修订与终止结果。
service、生成器和 tenant/thread 身份通过 LangGraph `context_schema` 注入，不存入可演化 state。
原始像素、密钥、完整指南正文和思维链不进入 graph state。

### 2.2 模型选择与硬边界

主决策通过 `tbx_react_decision` 严格 JSON Schema 返回语义任务，执行器结合当前状态解析为动作。
该路径不先调用原生 tool calling，也不额外调用独立意图解析器。模型失败后才采用受限规则托底；
模型动作和规则动作都由代码检查权限、参数、病例状态与预算，不执行自由文本工具名。
直接回答和通用问答正文都视为不可信输出。统一校验会剥离完整的封闭推理
标签，并拒绝残留 `thought/思考`、内部病例/Plan/ReAct 载荷或无关病例状态；拒绝结果不会直接展示。

以下情况由代码硬门控：

- 急症关键词命中时强制进入紧急提示动作；
- 技术失败、不可安全处理的冲突或能力缺失时受控重规划或停止；
- 预算用尽时不继续调用工具；
- 已完成或失败的动作不能通过模型要求无限重跑；
- 没有病例时不能调用依赖胸片的动作。
- 用户明确禁止的分类、检测或分割不能被模型、依赖补全或规则托底重新启用。

正常 v4 在工具失败后根据剩余目标回到 `decide` 或结束；`replan` 保留给兼容与规则降级路径。
轨迹仅保留修订原因码与计数，不保留自由 Reflection 或思维链。容量饱和且 receipt 明确标记
`retryable=true` 时，预算内对同一受限 invocation 恰好重试一次，两个尝试均保留真实 receipt。

### 2.3 Observation 与终止

每次工具执行都返回结构化 receipt，包括动作/工具、状态、耗时、Observation code、输入输出哈希和
citation 数量。服务随后重新读取病例，而不是假设工具已经改变状态。检测结果为空必须依赖明确的
“检测器已完成但无候选”状态；空数组本身不能证明检测器运行过。

`finalize` 表示本轮目标已满足，或存在明确且可解释的能力/证据缺口。技术失败或预算耗尽
不等于已创建临床会诊；只有批量筛查工作流会创建复核工作台任务。

## 3. 视觉证据的独立性

三分类器和 D-FINE 保持独立：

- 分类分流只使用三分类 argmax；
- D-FINE 仅在定位问题或复合任务确实需要位置证据时运行；
- D-FINE 有框、无框或失败都不修改分类结果；
- 定位有框或无框都不是第二个疾病分类结论，不与三分类形成分支冲突；
- 定位成功但无框时记录 `completed_no_detection`，正常结束位置任务，不重复调用直到“出现框”；
- 肺野/空间关系只解释候选框位置，不判断活动性、传染性、菌阳性或耐药。

图像质量检查提供工程 warning，不足以验证投照体位、是否为目标人群或是否达到诊断质量。DICOM
支持限定为受控的单帧单色 CR/DX 路径；部署方仍需完成合法取得、去标识化、访问控制和留存策略。

## 4. 指南检索边界

所有检索模式读取同一份经审核的 `source_manifest.json` 与 `chunks.jsonl`。chunk 在排序前受
`retrievable`、审核状态、jurisdiction、topic、日期和 claim scope 约束。citation 保留稳定
`chunk_id`、来源、章节/页码定位和支持文本。

BM25、Dense 或 Hybrid 的排名分数都不是医学置信度。Dense 索引还必须与 corpus hash、模型 ID、
模型制品 SHA-256、revision、向量维度和 generation manifest 一致；不匹配时不能静默复用旧索引。
若部署允许稀疏降级，receipt 必须写明实际使用 BM25 及降级原因，不能把降级结果标记为 Hybrid。

仓库的固定 query/qrels 是软件工程 fixture，只用于检查检索接线、稳定 ID、失败分类和排名回归。
它没有经过医学相关性标注，不得用来证明检索质量或选择临床阈值。

## 5. 上下文与持久化

服务保存病例结构化状态、线程的有限最近消息摘要、工具计数、最近一次成功且可续接的语义意图和
审计事件。每轮重新从病例事实构建简洁上下文；不把上一轮自然语言回答当作医学事实来源。
正常 v4 由模型结合最近一对交互判断“继续”“展开”等追问的当前目标，运行时检查权限、缓存和证据。
受限意图记忆也供规则降级路径使用，不能据此保证真实模型在所有追问中都不会选错目标。

当前 LangGraph 未配置 durable checkpointer，不支持中断后从图中间节点恢复一轮 Agent 执行。真正持久化的是业务
SQLite/病例制品；这是避免医疗状态被两套存储重复写入的显式取舍。同一 tenant/user/thread 在单进程内串行，
但多进程分布式锁、跨组件事务和自动恢复尚未实现。

公开轨迹记录脱敏 Plan、修订原因码、ReAct 动作、真实 LangGraph 节点名、工具收据、预算和终止原因；
`hidden_reasoning_persisted=false`。它提供可评测的执行来源，不保存自由思维链。该声明不依赖 provider
自行隐藏推理；输出层仍执行独立清洗与拒绝，避免模型把“思考”作为普通正文返回给用户。

## 6. LLM 与 OpenAI-compatible 接口

LLM 负责结构化语义决策与普通回答，工具事实由运行时拥有：

- 复合或条件决策可登记公开 Plan，计划节点直接整理已生成 tasks，不额外调用规划 LLM；
- `decide` 返回语义任务，运行时映射为一个允许工具、按需计划或回答；
- 病例与知识回答主要组合可信工具事实，不要求每轮另调一个语言合成 LLM；
- 能力说明和既有病例摘要由代码拥有的可信投影生成，不由 LLM 根据私有上下文自由概括；
- 所有模型直答在展示前检查思考前缀、内部状态回显和无关病例状态；
- 原始胸片不发送给文本 LLM；
- 模型不能修改分类值、候选框、citation 或工具状态；
- LLM 失败时保留确定性结果，不生成模拟医学证据。

本地 MedGemma/llama.cpp 和外部 OpenAI-compatible 服务使用同一 Agent 边界。选择远程服务会把本轮允许的
文本上下文发送给该服务，部署方必须自行评估传输、日志、地域和留存。直接访问底层模型的
`/v1/chat/completions` 会绕过病例、工具、RAG 和安全校验，不能称为 TBX-Agent 输出。

## 7. 典型失败场景

| 场景 | 当前行为 | 不应发生的行为 |
| --- | --- | --- |
| 未上传胸片却请求分类/定位 | 返回“请先上传胸片”，不调用视觉模型 | 用通用知识猜测影像结果 |
| 分类已完成，再问病灶位置 | 只按需调用定位；完成后重新检查状态 | 再次分类或把分类分数当位置 |
| 检测器完成但无框 | 记录 `completed_no_detection`，正常结束位置任务 | 写成“没有病灶”、改写分类或无限重试 |
| 分类/定位/解剖工具失败 | receipt 标记失败，图根据依赖关系受控重规划或停止 | 把失败当阴性、伪造 mock 结果 |
| 问“和半年前相比”但无可验证纵向能力 | 零工具说明当前不能比较 | 用当前片推断恶化/好转 |
| Dense 索引缺失或指纹不匹配 | 按配置失败关闭或显式 BM25 降级 | 静默声称使用 Hybrid |
| LLM 返回未知动作或非法 JSON | 丢弃输出，进入受限 `replan` 或最低限度托底 | 执行模型提供的自由工具名/参数 |
| LLM 把 `thought/思考`、`case_state` 或 Plan 载荷写入正文 | 清洗可安全分离的封闭块；否则拒绝并走受控回答路径 | 把模型思考、私有运行状态或病例诊断化改写展示给用户 |
| 用户请求产品能力或已完成分析摘要 | 零工具返回代码拥有的能力事实或公开病例证据投影 | 泛化成“各种任务”的通用 AI，或让模型复述私有病例状态 |
| 证据冲突或预算耗尽 | 受控终止并记录原因码 | 继续消耗资源或强行生成结论 |

## 8. 数据、身份与审计

仓库不应包含患者图像/DICOM、病例数据库、模型权重、向量索引、API 密钥或原始版权指南。
这些运行资产必须放在 Git checkout 外；公开源码构建器会拒绝常见患者格式、数据库、权重、归档、
凭据和工作站绝对路径。

research/development 档位的身份信息由客户端提供，只适合本机研究。production 档位存在 HMAC
反向代理边界和 tenant/subject 隔离，但仍不等于完整机构 IAM、RBAC 或跨 subject 临床授权。
SQLite、普通文件和 SHA-256 审计链也不是加密存储、数字签名或 WORM 审计。

## 9. 已覆盖的工程验证

仓库测试当前覆盖的重点包括：

- 真实 `StateGraph`/已编译图、固定节点拓扑、条件重规划和生产 `invoke` 路径；
- 公开 Plan、四工具单动作 allowlist、LLM 越权拒绝、JSON 兼容 fallback 和预算终止；
- 工具成功/失败后的状态重建、稳定 Observation code 与公开轨迹；
- 分类 argmax 不被检测器覆盖、检测器未运行与已运行无框的区分；
- 既往片缺失、纵向能力缺失、索引不匹配和依赖缺失等失败分支；
- 指南 metadata/claim-scope 门控、citation 完整性和检索 fixture；
- tenant/subject 病例访问、批量复核版本冲突、报告路径约束；
- mock 与真实后端标记、真实后端失败关闭及启动预检。

这些测试只说明给定输入下的软件行为，不能证明临床敏感度、特异度、真实世界安全性、知识完整性、
人因安全、隐私合规或网络安全。

## 10. 真实部署前仍缺少什么

在任何真实照护流程使用前，至少还需要：

1. 目标地区临床、影像、结核病、药学和急诊负责人审核输出、主动筛查和人工处置 SOP；
2. 所部署视觉模型在独立目标人群、设备、机构和亚组上的外部验证与校准；
3. 医学双审 qrels、冲突/时效审查以及 Dense/Hybrid 的固定工件、恢复、负载和失败注入评测；
4. 机构身份、最小权限 RBAC、TLS、密钥管理、静态加密、PHI/OCR 检测和删除/备份策略；
5. 多 worker 共享锁/限流、幂等/outbox、审计外部锚定、监控、回滚和事故响应；
6. 纵向影像模型、人工最终裁决模型和经过签署的最终报告版本；
7. 适用的医疗器械、隐私、网络安全和数据跨境合规评估。

任何单元测试、模型分数、预检成功或指南文档数量都不能单独解除这些缺口。
